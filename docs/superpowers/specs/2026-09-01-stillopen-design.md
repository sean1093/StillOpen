## 1. 問題

**現在（週日晚上／深夜／連假），我附近哪一間健保特約診所或藥局還開著？**

今天回答這個問題的方式全部很爛：

- **Google Maps 的診所營業時間結構性錯誤。** 診所是「早診／午診／晚診」三段制，不是連續營業。Google 的 `opening_hours` 模型無法表達「週三上午看診、下午休診、晚上看診」，商家自填也幾乎沒人維護。
- **健保署官網有正確資料，但要點五層選單**，且一次只能查一家。
- **第三方 App**（掛號類）多半只涵蓋有簽約的院所，不是全國名冊。

而這個問題的答案，實測後發現比想像中稀缺得多。

### 1.1 稀缺性實測（2026-09-01，全量拉取 24,736 筆）

| 條件 | 家數 | 佔比 |
|---|---:|---:|
| 診所名冊原始筆數 | 24,736 | |
| 合約仍有效（`CLOSESHOP > 今日`） | 22,102 | 89.4% |
| 平日晚上有開 | 18,706 | 84.6% |
| 週六下午有開 | 9,963 | 45.1% |
| **週日任一時段有開** | **2,665** | **12.1%** |
| **週日晚上有開** | **922** | **4.2%** |

切科別後更極端：

| 科別 | 全台 | 週日有開 | 週日晚上 |
|---|---:|---:|---:|
| 兒科 | 1,364 | 418 | **169** |
| 耳鼻喉科 | 1,111 | — | **161** |
| 牙科 | 7,024 | 440 | — |

**兒科 · 週日晚上，全台分佈：**
`臺中 46 · 新北 27 · 桃園 22 · 高雄 21 · 彰化 12 · 臺南 11 · 臺北 7 · 南投 5 · 新竹 4 · 宜蘭 3 · 雲林 3 · 嘉義市 2 · 花蓮 2 · 嘉義縣 1 · 屏東 1 · 澎湖 1 · 金門 1`

台北市，整座城市，星期天晚上，**7 家**。

藥局狀況好很多（10,128 家中 7,609 合約有效，週日晚上仍有 3,345 家）。
**痛點高度集中在診所。**

### 1.2 這個稀缺性決定了整個設計

當候選只剩 7 家，「誰最近」不需要演算法 —— 全部列出來、標行政區、附電話，使用者自己判斷哪個順路。

> **推論：最需要距離排序的時候，候選數量最少。**
> 所以 v1 不做地理編碼、不做定位、不做地圖。見 §6。

## 2. 產品定義

**一句話：** 選你的行政區，看此刻還開著的診所與藥局。

**刻意服務的時段：** 週末、每日 18:00 後、國定假日。
平日白天全台有 18,706 家診所在營業 —— 那不是問題，不需要工具。

**產出的是答案，不是資料。** 進站即見清單，不是搜尋框、不是地圖圖釘、不是表格。
（延續 VeggieRadar 的 board-first 原則。）

### 2.1 非目標（v1 明確不做）

| 不做 | 理由 |
|---|---|
| 距離排序 / 地圖 / GPS 定位 | 見 §1.2；且名冊無座標，需額外地理編碼（§6） |
| 醫院 | 醫院有自己的掛號與急診系統，痛點不同 |
| 看診進度 / 掛號 | 全台無統一 API，需逐院爬蟲，維運地獄 |
| 帳號 / 收藏 / 推播 | 沒有它也能解決問題 |
| 連假專屬看診時段 | 上游無機器可讀管道（§5.3） |

## 3. 資料來源

全部免金鑰、每日更新、授權為**政府資料開放授權條款第 1 版（GODL-1.0）**，義務僅為顯名標示。

| 資料 | Resource ID | 筆數 | 更新 | 存取 |
|---|---|---:|---|---|
| 健保特約醫事機構－診所 | `A21030000I-D21004-009` | 24,736 | 每日 | ✅ CKAN datastore |
| 健保特約醫事機構－藥局 | `A21030000I-D21005-001` | 10,128 | 每日 | ✅ CKAN datastore |
| 特約院所固定服務時段 | `A21030000I-D21006-001` | 30,221 | 每日 | ✅ CKAN datastore（交叉驗證用） |
| 政府行政機關辦公日曆表 | dgpa CSV，每年一檔 | — | 每年 | ✅ 直接下載 |

**端點格式：**

```
https://info.nhi.gov.tw/api/iode0010/v1/rest/datastore/{resourceId}?limit=1000&offset={n}
```

CKAN 相容，`limit` 上限 1000，需分頁。**實測全量 24,736 筆分 25 頁拉完耗時 1.6 秒。**

OAS 文件：`https://info.nhi.gov.tw/IODE0000/openapi.json`

### 3.1 診所／藥局欄位

```
HOSP_ID, HOSP_NAME, HOSP_CODE_CNAME, TEL, ADDRESS, BRANCH_TYPE_CNAME,
SPECIAL_TYPE, SERVICE_CNAME, FUNCTYPE_CNAME, CLOSESHOP,
HOLIDAYDUTY_CNAME, HOLIDAY_REMARK_CNAME, GOVAREANO, CONT_S_DATE
```

關鍵欄位：

- **`HOLIDAYDUTY_CNAME`** — 人類可讀的週時段字串，21 段以「、」分隔：
  `星期一上午看診、星期二上午看診、…、星期日晚上休診`
  順序固定為「週一~日上午」→「週一~日下午」→「週一~日晚上」。
- **`CLOSESHOP`** — 合約終止／歇業日（`YYYYMMDD`）。**每筆都有值**，是合約迄日不是空欄。
  實測 24,736 筆中有 **2,634 筆已過期**。不濾就是給使用者錯的答案。
- **`FUNCTYPE_CNAME`** — 診療科別，逗號分隔（`內科,眼科,復健科,中醫一般科`）。
- **`HOLIDAY_REMARK_CNAME`** — 自由文字備註，1,949 家有填實質內容。
  例：`成人疫苗僅於星期一、二、五提供。幼兒疫苗僅於星期三、四早上提供。`
  **這是 Google Maps 永遠不會有的資訊，必須完整呈現。**
- **`ADDRESS`** — 完整中文地址，**含全形數字**（`南京東路４段１３３巷５弄１號`）。無經緯度。
- **`GOVAREANO`** — 戶役政縣市代碼。

### 3.2 沒有座標

診所與藥局名冊皆**無經緯度欄位**（已實測 14 欄全數確認）。取得座標的全部合法管道已查證：

| 管道 | 額度 | 可否快取公開 | 結論 |
|---|---|---|---|
| TGOS 批次地址比對（內政部） | 免費 1 萬筆／日 | ✅ GODL-1.0 允許重製散布 | v2 採用 |
| NLSC 全國門牌定位 | — | — | ❌ 限政府／國營／學術 |
| 全國門牌座標開放資料集 | — | — | ❌ **不存在**（陳情 #21721 自 2015 未實現） |
| OSM Nominatim | 1 req/s | ODbL，須 share-alike | v2 補漏用 |

參考先例：長照 ABC 據點（`data.gov.tw/dataset/88270`）**已內建經緯度**且每日更新 —— 證明衛福部有能力發布含座標的機構名冊，只是診所名冊尚未跟進。

## 4. 架構

健保署資料每日只更新一次 → **不需要後端。**

```
GitHub Actions（每日 07:30 CST，健保署 07:00 左右更新完畢）
  │
  ├─ 拉 D21004 (24,736) + D21005 (10,128)，CKAN 分頁
  ├─ 過濾 CLOSESHOP <= today
  ├─ 解析 HOLIDAYDUTY_CNAME → 21 字元 bitmap
  ├─ 交叉驗證 D21006 bitmap（不一致 → warning）
  ├─ 由 ADDRESS 解析 縣市 / 行政區
  ├─ 健全性檢查（§5.4）→ 未過則 abort，不覆蓋舊資料
  └─ 產出 data/ 靜態 JSON，commit 進 main
  │
GitHub Pages（由 main 建置）
  └─ 前端只 fetch 使用者所在行政區的那一個檔
```

**沒有後端、沒有資料庫、沒有 API 金鑰、沒有 runtime 外部依賴。**
（比 VeggieRadar 更簡單 —— 後者需要 GAS 是因為 MOA 行情要即時查詢。）

**排程時間的實作陷阱：** 實測健保署 `modified` 時間戳為 `2026-08-31 07:02:26`
與 `2026-09-01 07:03:16`（CST），故排在 07:30 CST。
GitHub Actions 的 `cron` **一律是 UTC**，07:30 CST 要寫成 `30 23 * * *`（前一日 UTC）。
此處寫錯會固定拿到前一天的資料，而且不會報錯。

### 4.1 為什麼把產出的資料 commit 進 repo

- build 失敗自然就是不 commit → 站台繼續服務昨天的資料，天然 fallback
- git 歷史即資料稽核紀錄（哪天哪家診所改了時段）
- Pages 直接從 main 建，無額外 artifact 管線

估算：24,736 + 10,128 筆切成約 370 個行政區檔，平均 ~90 筆／檔 ≈ 18 KB。
總量約 5–7 MB，每日 diff 極小（排序穩定）。
**監控項：** 若一年後 git 歷史膨脹超過 500 MB，改為 `data` orphan branch 定期 squash。

### 4.2 產出格式

```
data/index.json          縣市 → 行政區 → { file, counts }
data/{cityCode}/{district}.json
```

`index.json` 的 `counts` 讓選單能直接顯示「臺北市 大安區 · 週日晚上 2 家」，
使用者在點進去之前就知道有沒有東西。

每筆院所（以下為 2026-09-01 實際資料，未經修改）：

```jsonc
{
  "id": "2101020019",
  "name": "臺北市立聯合醫院附設大安門診部",
  "kind": "clinic",              // clinic | pharmacy
  "cat": "一般診所（醫務室）",
  "tel": "(02)27390997",
  "addr": "臺北市大安區辛亥路３段１５號",
  "spec": ["家醫科"],
  "open": "NNNNNYYNNNNNYYYYYYYYY",  // 21 char, N=看診 Y=休診
  "note": "成人疫苗僅於星期一、二、五提供。幼兒疫苗僅於星期三、四早上提供。"
}
```

`open` 直接沿用健保署編碼（`N`=看診、`Y`=休診），**不做語意反轉** —— 少一層可能出錯的翻譯。
索引：`0-6` 週一~日上午、`7-13` 下午、`14-20` 晚上。

## 5. 關鍵設計決策

### 5.1 時段只有三格，沒有鐘點

健保署只提供「上午／下午／晚上」，**不提供具體開始結束時間**。這是無法繞過的上游限制。

產品自訂對照（明白寫在頁面上）：

| 格 | 對應時間 |
|---|---|
| 上午 | 08:00 – 12:00 |
| 下午 | 14:00 – 18:00 |
| 晚上 | 18:00 – 21:00 |

落在 12:00–14:00 或 21:00 之後 → 顯示「多數院所午休／已打烊」，並直接給出**下一個時段**的清單，不讓畫面空著。

### 5.2 位置：v1 手選行政區

不做 GPS、不做地理編碼。使用者選一次縣市＋行政區，存 `localStorage`，之後進站直接命中。

理由：
- 台灣人知道自己在哪一區
- 稀缺時段的候選數量小到不需要距離（§1.2）
- 零 API、零成本、零失敗模式

### 5.3 連假：誠實降級

`辦公日曆表` 判斷今天是否為放假日／補班日。

- **放假日** → 以該日實際星期別查詢，並顯示警語：
  「今天是國定假日，院所看診時段可能與平日登記不同，建議先電話確認」
  **不假設國定假日等同星期日** —— 那是錯誤推論。
- **補班日**（週六上班）→ 顯示「今日補班，多數院所仍依星期六時段」

**已知缺口：** 健保署確實有「特約院所特定假期服務時段」資料集（`A21030000I-D21007`），
內容正是連假期間的逐日開診狀況。但實測：

- datastore API 對 `-00J` / `-00K` / `-001` 三個 resource ID 皆回 `Not found`
- 官方下載連結 `info.nhi.gov.tw/Dataset?rId=…` 回傳 JS 轉址頁，非 CSV
- 目前僅存兩份資源，皆為「115 年兒童節及清明節連假」，最後更新 2026-04-01（已 5 個月未動）

→ **v1 不使用此資料集。** 若日後上游開放機器可讀管道，這是 v2 最高優先的補強項。

### 5.4 錯誤處理

Build 端（失敗即 abort，**絕不覆蓋既有資料**）：

| 檢查 | 門檻 | 行為 |
|---|---|---|
| 診所筆數 | < 20,000 | abort |
| 藥局筆數 | < 8,000 | abort |
| `HOLIDAYDUTY_CNAME` 解析失敗率 | > 1% | abort |
| 地址無法解析出行政區的比率 | > 2% | abort |
| D21004 文字 vs D21006 bitmap 不一致 | 任一筆 | warning（不 abort，記錄筆數） |

前端：
- `fetch` 失敗 → 顯示上次成功的快取（`localStorage`）＋ 明確標示資料日期
- 每一頁固定顯示資料日期，不隱藏新鮮度

### 5.5 誠實邊界（必須出現在 UI 上，不是藏在 About 頁）

1. 看診時段是院所**每月申報**，臨時休診抓不到
2. 「晚上」不保證營業到幾點
3. 連假期間可能另有安排
4. **本站提供的是候選清單與電話，不是保證。出門前請先打電話。**

## 6. v2（已定義，不在本次實作範圍）

距離排序。做法已查證確定：

1. TGOS 批次地址比對（免費 1 萬筆／日）**只跑稀缺子集** ——
   週日有開的診所 2,665 + 藥局 4,237 ≈ **6,900 筆，一天額度內跑完**。
   平日白天有開的 18,706 家不需要座標。
2. 前處理：全形→半形、「臺／台」正規化，提升命中率
3. TGOS 未命中者以 Nominatim 補（1 req/s、單執行緒、結果必須快取）
4. 前端 `navigator.geolocation` + 直線距離排序
5. 顯名聲明加上「內政部資訊中心 TGOS」與 OSM／ODbL

## 7. 技術選型

| 層 | 選擇 | 理由 |
|---|---|---|
| 前端 | Vite + TypeScript + Tailwind | 與既有專案一致 |
| Build script | Node + tsx，與前端共用型別 | 單一語言，資料契約不會漂 |
| 排程 | GitHub Actions `schedule` | 免費，與資料同 repo |
| 佈署 | GitHub Pages（from main） | 零成本，無 runtime |
| 測試 | Vitest | 與既有專案一致 |

視覺延續 VeggieRadar 的 MUJI 調性：紙感底、墨色字、細線分隔、留白。
UI 繁體中文；程式碼、註解、文件英文。

## 8. 測試策略

只測會壞的東西。

| 對象 | 方式 |
|---|---|
| `HOLIDAYDUTY_CNAME` → bitmap 解析 | 單元測試，真實 fixture：全休診／全看診／混合／空字串／格式異常 |
| 地址 → 縣市＋行政區 解析 | 單元測試，含直轄市、縣轄市、鄉、區、原住民族地區 |
| `CLOSESHOP` 過期過濾 | 單元測試，邊界值（等於今日、早一天、晚一天） |
| 「現在是哪一格」時段判斷 | 單元測試，含 12:00–14:00 與 21:00 後的空窗 |
| D21004 vs D21006 一致性 | Build-time 交叉驗證，輸出不一致筆數 |
| 上游格式漂移 | §5.4 的健全性門檻，build 直接 abort |

**不做** E2E、不做視覺回歸、不對 GitHub Actions 本身寫測試。
